# 새인 인스타: IT 카드뉴스 3장 만들기

결과물은 **PNG 3장**이다. 1p 썸네일, 2p 내용(`1.`), 3p 정리(`2.`)로 구성된다.
디자인은 `assets/`에 코드로 고정돼 있다. 너는 **카피(card.json)만 쓰고, 렌더러를 돌리고, 검사를 통과시킨다.**

## 절대 규칙
1. **디자인을 만들거나 바꾸지 않는다.** HTML·CSS를 새로 쓰지 않고, `assets/`의 파일을 수정하지 않는다. 색·배치·폰트를 바꾸자고 제안하지 않는다. 카드 이미지는 반드시 `scripts/render.js`로만 만든다. (사용자가 디자인 변경을 명시적으로 요청한 경우는 예외. `assets/cards.css`만 수정한다.)
2. **이미지를 생성하지 않는다.** 제품을 SVG·캔버스로 그리지 않고, AI 생성 이미지를 쓰지 않는다. 사진은 사용자가 준 파일이나 사용자가 준 URL(공식 보도자료)만 쓴다.
3. **카피는 `references/copy-rules.md`를 지킨다.** 작성 전에 이 파일을 반드시 읽는다.
4. **검사 통과(`"ok": true`) 전에는 완성이라고 말하지 않는다.** `_preview` 파일은 최종본이 아니다.
5. **확인하지 않은 숫자를 쓰지 않는다.** 모르면 "미공개"로 쓴다.

## 진행 순서

### 1단계. 재료 확인
필요한 재료는 **기사**(링크·본문·주제)와 **제품 사진**이다.
- 기사 링크나 본문이 있으면 그 내용을 기준으로 쓴다. 링크는 직접 읽는다.
- 주제만 있으면 웹 검색으로 최신 기사를 찾는다. 출처 우선순위는 제조사 뉴스룸 → 주요 IT 매체(국내외) → 커뮤니티(루머 전용)다. 같은 사실을 2곳 이상에서 확인한다.
- 사진이 없으면 멈추지 않고 카피부터 만든다. 끝에 `imageBrief`를 보여주며 사진을 요청한다. 사진 없이는 `--preview`로 레이아웃만 보여줄 수 있다.
- 사진이 URL이면 내려받아 쓴다. 다른 매체의 워터마크가 있으면 쓰지 말고 사용자에게 알린다.

### 2단계. 사실 정리 (작성 전 메모)
카드에 쓸 사실을 먼저 목록으로 뽑는다: 제품명, 발표일, 핵심 변화 2~3개, 전작 대비 수치 3개, 객관적 단점 2개. 항목마다 출처를 붙인다.
- 전작 스펙이 기사에 없으면 전작 공식 스펙이나 신뢰 매체로 확인한다. 확인이 안 되면 그 항목을 비교에서 빼고 다른 항목을 고른다.
- 공식 발표가 아니면 status를 "루머"나 "유출"로 정한다.

### 3단계. card.json 작성
`references/copy-rules.md` 형식으로 작업 폴더에 `card.json`을 저장한다. 쓰는 동안 글자 수를 한 칸씩 센다.

### 4단계. 렌더 + 검사
```bash
node <스킬 폴더>/scripts/render.js --data card.json --cover <사진> --out <출력 폴더>
```
- 옵션: `--bg <사진>`(2p·3p 배경 따로), `--x 0~100 --y 0~100 --zoom 100~200`(1p 사진 위치), `--preview`(위반이 있어도 미리보기)
- 출력 폴더는 사용자가 받을 수 있는 곳으로 한다. claude.ai라면 `/mnt/user-data/outputs`이다.
- 결과는 표준출력 JSON이다. `ok`, `errors`, `files`가 들어 있다. 종료 코드는 0 통과, 2 규칙 위반, 1 실행 오류다.
- **실행 오류(playwright 없음 등)일 때:** `npm i playwright && npx playwright install chromium`을 한 번 시도한다. 그래도 안 되면 `--studio`로 수동 스튜디오 폴더를 만들어 통째로 전달한다. 사용자는 `studio.html`을 열어 "PNG 3장 저장"만 누르면 된다.

### 5단계. 위반 고치기 (반복)
`ok: false`이면 `errors`의 각 항목이 가리키는 **그 칸만** 고치고 4단계를 다시 돌린다.
- 최대 5회 반복한다. 같은 칸이 계속 걸리면 단어를 깎지 말고 문장 구조를 바꾼다.
- "넘침" 오류는 글자 수가 맞아도 실제 화면에서 넘친 것이다. 더 짧게 쓴다.

### 6단계. 눈으로 점검
렌더된 PNG 3장을 직접 열어 본다.
- **1p:** 제품이 제목에 가려지거나 잘리면 `--y`나 `--zoom`을 조정해 다시 렌더한다. 제품은 위쪽 60% 안에 있어야 한다.
- **2p·3p:** 배경 사진이 밝아서 글자가 안 읽히면 더 어두운 사진을 `--bg`로 넣는다.
- **카피:** 형광펜이 의미 있는 단어에 있는지, 1p 질문에 2p·3p가 답하는지 본다.

### 7단계. 전달
짧게 다음을 전달한다.
1. PNG 3장 (파일로 전달)
2. 팩트체크 표: `카드 문구 | 근거 | 출처` (숫자가 들어간 문구 전부)
3. 사진 출처
4. 사진을 아직 못 받았으면 `imageBrief`와 함께 사진 요청

## 수정 요청이 오면
"제목 바꿔줘", "단점 다른 걸로" 같은 요청은 `card.json`의 해당 칸만 고치고 4~6단계를 다시 한다. 디자인을 손대지 않는다.

## 파일
- `references/copy-rules.md`: 카피 규칙과 JSON 형식 (작성 전 필독)
- `references/design-rules.md`: 디자인 규칙 (왜 이렇게 생겼는지. 디자인 질문이 올 때 참고)
- `scripts/render.js`: 렌더러 + 검사기
- `assets/`: 고정 디자인. `rules.js`(글자 수·금지어·브랜드명), `cards.css`(디자인), `engine.js`(검사·렌더), `studio.html`(수동 모드), `fonts/`(ONE 모바일고딕 Title·리디바탕), `fonts-data.js`(수동 모드 저장용 폰트 묶음)
