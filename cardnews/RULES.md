# IT 카드뉴스 규칙서

## 0. 왜 이렇게 만들었나

AI에게 "이런 디자인으로 만들어줘"라고 하면 매번 결과가 달라집니다. 규칙을 아무리 길게 써도 AI는 그 규칙을 **참고**할 뿐 **지키지는** 않기 때문입니다.

그래서 일을 셋으로 나눴습니다.

| 역할 | 담당 | 바뀌는가 |
|---|---|---|
| 디자인 (색·폰트·배치·여백) | `cards.css` 코드 | **절대 안 바뀜.** AI가 손댈 수 없음 |
| 글자 (제목·내용·비교표) | AI → JSON | 매번 바뀜. 단, 칸과 글자 수가 정해져 있음 |
| 검사 (규칙 위반 잡기) | `studio.html` 검사기 | 위반이 하나라도 있으면 **저장 버튼이 잠김** |

AI가 규칙을 어겨도 그대로 게시될 수는 없습니다. 이 구조 덕분에 가능한 일입니다.

---

## 1. 판형

- **1080 × 1350px (4:5)**. 인스타 피드에서 가장 크게 보이는 비율
- 좌우 여백 **80px**: 프로필 그리드는 3:4로 잘려 양옆이 34px씩 사라지는데, 이 여백이면 글자가 잘리지 않음
- 폰트 **Pretendard** 한 종류만 사용. 굵기로만 위계를 나눔 (800 제목 / 700 강조 / 500~600 본문)
- 자간 -0.03em, 단어 단위 줄바꿈(`keep-all`). 한글 제목이 어색하게 쪼개지지 않음

## 2. 색

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| 배경 | `#0B0B12` | 전 페이지 기본 (제품 사진이 가장 돋보이는 어두운 톤) |
| 포인트 | `#6C5CFF` | 태그, 형광펜 강조 (브랜드색 `#3B2BFF`을 어두운 배경용으로 밝힌 값) |
| 강조 글자 | `#B9B0FF` | 제목 속 [[강조]] 단어 |
| 경고 | `#FFB547` | 루머·유출 태그, "아쉬운 점" |
| 개선/아쉬움 | `#4ADE80` / `#FF6B6B` | 비교표 배지 |

포인트색은 **한 페이지에 한 가지 역할**만 합니다. 강조가 여러 개면 아무것도 강조되지 않기 때문입니다.

## 3. 페이지별 설계

### 1p 썸네일: 사진이 멈추게 하고, 제목이 넘기게 한다
- 제품 사진은 화면 전체(풀블리드). **위쪽 55%에 제품, 아래 45%는 제목 자리**
- 아래로 갈수록 검게 깔리는 그라데이션. 어떤 사진이든 흰 제목이 읽힘
- 제목은 104px, 2~3줄, 한 줄 최대 9자. 강조는 **딱 한 단어**만 색을 바꿈
- 태그(신제품/루머 등) + 키커(제품명 + 무슨 일)로 맥락을 먼저 주고, 제목은 궁금증만 남김
- 오른쪽 아래 "넘겨서 확인 →"로 넘길 이유를 줌
- 루머·유출 기사는 태그가 **주황색**으로 자동 변경. 공식 발표와 구분됨

### 2p 내용: 1p의 "왜?"에 답한다
- 배경은 커버 사진을 흐리고 어둡게 깐 것. 1p와 이어진 느낌을 주되 글자를 방해하지 않음
- 헤드라인 1줄 + 리드 1문장 + 핵심 3가지 카드
- 3개인 이유: 4개부터는 스와이프 중에 읽히지 않음
- 헤드라인 강조만 **형광펜 박스**(참고 이미지 2번 스타일). 나머지는 글자색 강조

### 3p 정리: 좋은 말만 하지 않는다
- 직전 모델과 4개 항목 비교표. 개선/아쉬움/동일/NEW 배지가 자동으로 붙음
- "아쉬운 점" 2개는 필수. 광고처럼 보이지 않게 하는 장치이자 신뢰도의 핵심
- 한줄 정리: 누구에게 추천하는지로 마무리 (저장·공유 유도)
- 하단에 출처와 기준일 자동 표기

## 4. 사진 규칙 (사람이 지킬 것)
1. **제조사 공식 보도자료 사진만** 사용 (삼성 뉴스룸, 애플 뉴스룸 등). 루머 기사는 출처에서 공개한 렌더링 이미지를 쓰되 태그가 "루머/유출"인지 확인
2. **AI 생성 이미지 금지.** 없는 버튼, 틀린 카메라 배치 같은 "가짜 제품"이 만들어져 신뢰도가 무너짐
3. 세로로 긴 사진이나 여백이 넉넉한 사진을 고름. 제품은 위쪽 절반에 오게 슬라이더로 맞춤
4. 워터마크가 있는 타 매체 사진 금지
5. 해상도는 가로 1080px 이상

## 5. 글 규칙 (AI가 지킬 것, 검사기가 잡음)

자세한 내용은 `PROMPT.md`에 있습니다. 검사기가 자동으로 잡는 항목은 다음과 같습니다.

- 정의된 칸 외 항목 추가 / 필수 칸 누락
- 칸별 글자 수 초과 (공백 포함)
- 개수 (제목 2~3줄, 포인트 3, 비교 4, 단점 2, 출처 1~3)
- [[강조]] 개수
- 정해진 선택지 밖의 값 (태그, 상태, change)
- 루머/유출인데 공식처럼 표시
- 비교표 논리 오류 (값이 같은데 "개선" 등)
- 금지어 23개, 이모지, 느낌표, 물결, 말줄임표, 마크다운 기호, 이중 공백
- **실제 렌더링 넘침**: 글자 수를 지켜도 화면에서 넘치면 탈락 (폰트 폭 차이까지 잡음)
- 커버 사진 미첨부

검사기가 **못 잡는 것**은 사람이 확인해야 합니다. 바로 **사실 여부**입니다. AI가 숫자를 지어낼 수 있으니, 저장 전에 2p·3p의 숫자를 원문 기사와 한 번 대조하세요.

## 6. 규칙을 바꾸고 싶을 때
- 글자 수, 금지어, 태그 종류: `rules.js` 수정 → `PROMPT.md`의 같은 숫자도 수정
- 색·폰트 크기·배치: `cards.css`만 수정
- 브랜드명·인스타 계정: `rules.js` 맨 위 `brand`, `handle`
